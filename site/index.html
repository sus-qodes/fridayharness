The pillars

What no harness gives you.

Four things Friday does around your agents — memory, tokens, intent and verification — and the governance that wraps them.

Pillar 01 · Memory

Every agent shares one memory.

Yesterday's decisions, today's failures, the graph of your code: Friday anchors it all beside your repo in an append-only local ledger. Every agent reads from it; none owns it. Events are appended, never rewritten — replay reconstructs the whole state of the project.

Replay from #0001 rebuilds goals, plans, decisions and verification — without any tool's session history.

Pillar 02 · Tokens

Stop feeding the whole codebase into every prompt.

Traditional agent loops re-read entire files — thousands of tokens — on every turn. Friday's token-saving engine serves pre-computed AST slices instead: just the symbols a task needs, assembled locally from the code graph. Answers stay precise; bills stay small.

context for task-07 · routes/api.ts LOCAL
the old loop 12,400 tok
Friday slice 890 tok
registerRoutes() struct Plan 3 call sites test helpers

Assembled from the pre-computed code graph — a stat per file, nothing re-read, nothing sent wholesale.

Pillar 03 · Intent

Your intent survives every retry.

A deterministic DAG breaks each goal into dependency-aware tasks, each editing its own isolated Git worktree. When a model fails or a syntax retry loops, your boundaries hold: file reservations and task edges are preserved mathematically, not by convention.

Goal Ship the events API
schema · done handlers · running docs · waiting
wt-07 · task-07 wt-08 · task-08 isolated worktrees — main untouched
pnpm-lock.yaml reserved by task-07 · migrations/** by task-08

Retries re-run the attempt — boundaries and reservations hold until the task ends.

Pillar 04 · Verification

AI can never lie to you.

Every finished task is treated as an unverified claim until automated linters, typechecks and test suites deterministically prove it passes. Only verified code merges into main — the model's word is never the gate.

A task completes when the checks pass — not when the model feels finished.
